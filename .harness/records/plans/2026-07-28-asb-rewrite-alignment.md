# agent-switchboard 0.5 Rewrite Alignment

## Decisions resolved

- Q1–Q3 (earlier rounds): the product promise is the complete documented surface; remote sources keep every documented form; coco becomes a builtin target.
- Q4 baseline: the v0.4.35 commits were pushed from the owner's other machine and pulled here (`1554d30`). Reconciliation done: the only 0.4.34→0.4.35 change is the managed-clone readiness step — additive, no frozen fact moved; readiness semantics join the frozen contracts below, and the sources acceptance floor grows to 2,476 test lines.
- Q5 delivery shape: staged replacement — build the new engine fresh, replace the old structure section by section on the hot path first (rules → skills → hooks → plugins/native → mcp → commands/agents → project scope), lift proven safety modules only where they serve the frozen design, port the 0.4.35 behavior tests per cell as each section lands, delete the old structure at the end; shipped as one v0.5.0 cut-over release with `main` releasable throughout.
- Design discipline (owner instruction, 2026-07-28): the 0.5 structure is designed from scratch from the product motivation and frozen before the existing sources are inventoried. The old implementation is a quarry: material carries over only where it serves the frozen design; anything serving no user intent is dropped, each drop listed with its reason; if the quarry reveals a real intent the design missed, the design updates explicitly, never silently. The frozen design lives in `2026-07-28-asb-rewrite-design.md`; where its command surface deliberately differs from 0.4, the change is enumerated (this subordinates the earlier "CLI unchanged" default to the frozen design).
- Design review gate, passed (2026-07-28): three blind designers + two judges produced the frozen structure; adversarial reviews (Grok design-first, 9 findings; Codex source-first, 25 findings) were each verified against 0.4.35 source and folded — the largest being manifests and convention recognizers joining the proof chain with provenance-bounded authority, the three collision-policy branches, slice-granularity conflicts, the `native` apply kind, per-source `pending` preview rows, and `remove` retiring selections with the declaration. The targeted re-check passed 11/12; the residual (convention adoption laundering into delete authority via the ledger) closed by carrying provenance into the ledger — arbiter verdict, final.

Defaults chosen (veto to change):
- TypeScript, Node ≥ 20, ESM, current dependency set, no new runtime dependencies. Package name and `asb`/`agent-switchboard` bins unchanged; the command surface follows the frozen design doc — 0.4-compatible wherever the intent surface matches, deliberate differences enumerated in the changelog.
- Dual-version contract while the other machine runs 0.4.x against the shared `~/.asb`: 0.5 does not change config.toml keys, the `state/hooks/*.json` v1 schema, or the library layout; the shared hook state stays the live ownership authority, read and written on every run (recognizer demotion and any expiry wait until both machines run 0.5); new ledger state is device-local only; acceptance includes running `asb sync --dry-run` under 0.4.x on shared state a 0.5 sync has touched.
- Remote plugin sources keep every documented form — plain clones, marketplace external-entry materialization, sparse-checkout subdir sources, `type = "subtree"` — rebuilt on the engine's single resolved-ownership model (one `resolveSource()` verdict instead of six ad-hoc predicates, which is the cure for the v0.4.33→34 fix saga); the existing 2,476-line sources test suite is the acceptance floor.
- Custom targets stay supported, declaratively: `[targets.<id>]` config tables become schema-validated target data rows (~40 lines in the new model instead of the 563-line compiler). The undocumented `~/.asb/extensions/*.mjs` code-loading seam is dropped, and coco ships as a builtin target — coco.mjs stays in place serving the 0.4 peer and is deleted only once the fleet is on 0.5.
- Config mutations ASB performs (enable/disable, source add/remove) become targeted key edits that byte-preserve all surrounding text, comments included; full-file rewrite of user TOML is retired. This is a narrow text-editing contract, not a general comment-preserving TOML serializer.
- Intentional output changes, enumerated in the changelog: `list --json` unifies to one envelope; the `agentSync` JSON field and the human sync-status column disappear (their data was never persisted); the `asb source` tombstone command goes.
- Valid Copilot v1 hook files inside plugins remain silently ignored (the behavior survives; the 105-line validator shrinks to a shape probe).
- Two new read-only commands rendered from the plan stage without writing: `asb status` (per target and section — current, stale, skipped, foreign; exists because real drift on this machine went unnoticed) and `asb explain <id|path>` (one target: source, owner, recorded vs current hash, desired content). The only user-facing additions in 0.5; `import`, `init`, and the picker are carried 0.4 intents reshaped.
- ~10k source lines is a forecast only — never a gate, never an argument for keeping or dropping a feature.

## Goal

The current implementation is too hard to maintain: the same pipeline is hand-rolled per content type and per target with diverging behavior, ownership of written files is inferred six different ways instead of recorded, and history is 92 fixes against 20 features. A previous slim-down failed structurally — its budgets were blown within two releases. Rebuild the product on clean engineering so changes become small and safe.

Product promise, decided: 0.5 supports the complete documented surface — all six content types (mcp, rules, commands, agents, skills, hooks), all targets (claude-code, claude-desktop, codex, cursor, gemini, opencode, trae, trae-cn, plus coco promoted to builtin), MCP distribution, project scope with its managed/exclusive/none modes and collision policies, profiles, and the full plugin-source matrix. Completeness is delivered through the engine — targets as data rows, content types as descriptors, modes as plan-stage policies — never through per-cell hand-rolled pipelines.

End state: agent-switchboard 0.5.0 does what 0.4.35 documents, implemented as one reconciliation engine — resolve desired state → plan against a recorded ownership ledger → apply → report. The only removals are internals: the undocumented `.mjs` extension loader (superseded by declarative custom targets + coco builtin), dead-in-source machinery, and expiry-dated legacy migration arms. Output changes are enumerated in the changelog. The other machine keeps running 0.4.x against the shared `~/.asb` until it upgrades, and nothing 0.5 writes may break it.

Examples:

- `asb sync -p aws` after cut-over → byte-identical target files versus the 0.4.35 baseline, except the enumerated intentional output changes; this is the smoke walk, with the ported 0.4.35 behavior tests as the real acceptance per cell.
- First 0.5 sync on a machine with existing 0.4 outputs → files ASB wrote under 0.4 conventions are adopted into the ledger and reported as adopted, not flagged as conflicts; genuinely foreign files still report as conflicts and are never touched.
- `~/.claude/settings.json` is a symlink into the Mackup store → sync writes through the link; the link survives, and an unchanged file is not rewritten.
- After a 0.5 sync here, the other machine runs 0.4.x `asb sync --dry-run` against the shared state → still works, hook ownership intact.
- `asb sync` with `codex@openai-codex` under `native_plugins` → the plugin is registered with Claude Code exactly as 0.4.35 does it, and an unchanged install reports up-to-date, not "written".
- An enabled plugin whose source is absent (the `rl-harness` steady state) → listed by `asb status` as missing with its configured path, one warning at sync, sync continues (0.4.35's plugin list omits it entirely).
- `asb sync` on an empty home → says there is nothing to do and points at the quick start; no bare success checkmark (0.4.35 prints "✓ Sync complete.").
- An enabled application whose directory is not detected → reported as skipped with the reason and an `assume_installed` pointer, never counted as "up-to-date" (0.4.35 folds it into the up-to-date tally).
- Zero MCP servers enabled → no target MCP file is created; 0.4.35 creates `~/.claude.json` containing an empty `mcpServers` key unprompted.
- `asb sync --dry-run` → from the same captured input, the listed actions equal the actions a real run attempts; apply-time failures are reported separately (walked 0.4.35: dry-run said MCP was up-to-date, the real run then wrote `.claude.json`).
- Any flag ordering of the same command → identical behavior across the whole surface, and a scoped `status` shows the layer it names (walked 0.4.35 counterexamples: `asb rule -P <dir> list` vs `asb rule list -P <dir>` diverge, and a project scope with an explicit empty selection still lists the user layer).
- `asb enable` picker, toggle one skill, save → config.toml keeps every comment and commented-out line.
- `asb status` → read-only, zero writes: per target and section, current / stale / skipped (reason) / foreign; would have named this machine's genuinely stale `taskboard` skill and `verification` rule, which 0.4.35 surfaces nowhere (its "Agent sync status" section reports "no sync recorded" for all agents immediately after a successful sync).
- One malformed `~/.asb/rules/<x>.md` → that entry reports an error, everything else syncs (an intentional change: 0.4 aborts the whole sync).
- Exclusion: a `~/.asb/extensions/*.mjs` file → one warning naming the removal, pointing at `[targets.<id>]`, and noting the file still serves 0.4 peers on the shared library; everything else proceeds.

## Design

The structure and semantics are frozen in `2026-07-28-asb-rewrite-design.md`, derived blind from the product motivation by an independent design round (three designers who never saw the 0.4 sources, two judges, arbiter synthesis), then reconciled against the 0.4.35 sources as a quarry. Its Quarry verdict records the four surface additions the materials forced — `import`, project `init`, the single toggle picker under `enable`, per-source refresh — plus the carried mechanics (cited by origin) and the drop list with reasons. Alignment-level commitments it implements:

- One reconciliation engine: a pure plan consumed identically by sync, dry-run, status, and explain; four write shapes (own-file, own-dir, region, keys) behind one interface — render-slice, hash-current, write, remove — so the owned slice is defined once; apps × types as data rows with the handful of genuine dialect functions; region for markdown hosts only, keys for TOML/JSON hosts; all edits to one host file grouped into a single atomic replace; ~11 modules.
- Ownership recorded in a machine-local ledger (XDG state dir, surviving cache wipes), proof hierarchy: ledger hash → own markers → byte-identity → predecessor records (hooks state and per-device project manifests) → conventional-layout recognizers. Adoption is loud (paths printed, provenance recorded, previewable) and probes every managed location against the full library inventory, deletion always requires proof re-checked at removal time, and removal is authorized only by deselection — an enabled component with absent source files is `missing`, never a removal, so a half-arrived library sync cannot cascade deletions. Updates carry the mirror protection: a user-edited owned target is a `conflict`, never overwritten, except under the documented project `takeover` collision policy. Creation is gated by the table's `create` column (kills the unprompted `.claude.json`).
- Peer contract quarantined in `peer.ts`: the shared hooks v1 state stays the live ownership authority read and written in the exact 0.4 schema (unknown fields preserved) while any machine runs 0.4.x; 0.5-only config keys are additive-only, provably tolerated by 0.4's `.passthrough()` schemas (verified at src/config/schemas.ts).
- Closed per-entry outcome vocabulary with reasons and accurate verbs, exit codes 0/1/2, a credential redactor on every reason string, and exactly three pre-write aborts: invalid config (with nearest-key suggestion), readiness failure, corrupt ownership state (fail closed). Same-machine runs serialize on one lock file; symlinks are written through with the temp file in the resolved parent so rename never crosses devices.
- The command surface vs 0.4 is enumerated in the design's drop list (per-type command trees collapse into `sync`/`status`/`explain`/`enable`/`disable`/`add`/`remove`/`import`/`init`); every walked exemplar's property carries to the new spelling.
- Acceptance is behavioral and structural, never a line count: 0.4.35 behavior tests frozen and ported per cell as sections land; unused-on-this-machine cells (commands, agents, gemini, claude-desktop, project modes) get table-driven engine tests; the enumerated intentional-change list; the smoke walk; a structural check that write/cleanup/ownership logic exists exactly once; and 0.5 strict config validation run against this machine's real `config.toml` and `aws.toml` before cut-over.

## Boundary

- Mutable: everything under `src/` and `tests/`, README and docs, package.json version. Work happens on a branch; `main` stays releasable throughout.
- Non-goal: no new compatibility-matrix cells in 0.5 — no hooks for cursor/opencode, no commands for trae, no cells beyond what 0.4.35 documents. The engine is what makes such cells cheap to add after 0.5; adding them here would turn a rewrite into open-ended feature work.
- Frozen external contracts: every output path and format in the target table (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md` + config.toml dialect, `~/.cursor/rules/asb-rules.mdc` frontmatter, gemini/opencode/trae layouts, `<root>/.mcp.json`, hook `settings.json`/`hooks.json` shapes, `${HOOK_DIR}` and `$HOME`-portable commands, `<!-- <id>:start/end -->` block delimiters, skill/plugin id grammar `name`, `plugin:skill`, `plugin@marketplace:skill`), config.toml/mcp.json keys with their documented semantics (including `[distribution.project]` modes and collision policies) and legacy input formats (`active`→`enabled`, `[agents]`+`[subagents]`, `~/.agent-switchboard` home), the `~/.cache/asb/<namespace>` clone layout and provenance marker, device-id hash inputs exactly `sha256(ASB_DEVICE_ID|hostname, NUL, agentsHome)`, and the 0.4.35 managed-clone readiness semantics (ordinary sync clones missing configured checkouts into the cache before distribution and never implicitly fetches an existing one; `--update` refreshes; `--no-update` disables refresh only; dry-run never clones or migrates — it reports pending readiness actions with target paths; a readiness failure stops the run before any distribution).
- Red lines: never delete or modify a file without recorded or provably derived ownership; no ASB metadata keys or markers in user configs beyond the existing documented ones; git credentials never persisted or printed; no `process.exit` before stdout flush; no npm publish, tag, or release from this task without an explicit go-ahead.
- Compatibility traps (do not "fix" these): config layers merge project > profile > user with arrays replacing wholesale — `applications.enabled` included, there is no user-layer exception; profile files are full selection sets, not patches; scoped selector editing shows only that layer's explicit values, never inherited ones; array order is composition priority; codex/gemini/opencode write distinct global rules files and share one `AGENTS.md` only at project scope (write once, conflict on divergence); Codex `.system` skills dir is reserved; trae/trae-cn reserve each other's ids; Trae MCP entries omit `type`; Claude project MCP lives at `<root>/.mcp.json`, not `.claude/.mcp.json`.
